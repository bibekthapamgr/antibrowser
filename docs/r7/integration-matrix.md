# R7 — Integration matrix

Each row: what is proven automatically (and where), and what only the pilot on real Windows x64 / macOS arm64
computers can prove. "Automated" means it runs in CI on every relevant change. Results of the manual runs go into
[launch-checklist.md](launch-checklist.md).

| # | Journey | Automated evidence | Still manual (pilot, real devices) |
|---|---|---|---|
| 1 | New user: website → register → verify e-mail → one workspace + trial → download → sign in → open a profile | CI `deploy-scripts` → "production server behind TLS (R6)": signup with e-mail verification and desktop sign-in over the public https names, no tunnel; `onboarding.test.ts` (one workspace, one trial, races, interrupted bootstrap); `web.test.ts` (web and desktop are one account); `portal.test.ts` (only a verified signed release is offered); `apps/desktop/src-tauri/tests/browser.rs` (real Chromium profiles open, isolate, survive restarts) | Install the signed build from the download page, sign in, open a profile — on Windows x64 and macOS arm64, by a real new person without staff help |
| 2 | Paid checkout; delayed webhook shows pending; the verified event activates the right limits everywhere | `billing.test.ts` "a successful payment activates the plan; the redirect back alone changes nothing", "an outage never locks a paid organization out at once"; `portal.test.ts` "pays through the portal return: pending until the provider confirms…" (one subscription endpoint serves portal and desktop); `admin.test.ts` customer detail; Stripe sandbox suite when its secret is set | One real test-mode purchase on staging watched in portal, desktop and console |
| 3 | Owner shares exactly 10 of 50 profiles; the member needs no plan and cannot discover the other 40 | `team.test.ts` "owner shares exactly 10 of 50…" — R7 adds: name search for hidden profiles, export, workspace counts, automation jobs and the member's own API token all reveal nothing; `cross-tenant.test.ts`, `authorization.test.ts`, `automation.test.ts` | Same flow in the desktop apps with a real invited member |
| 4 | Returning 0.12.x user upgrades: no duplicate linked profiles, local-only stays local, snapshots/keys survive, agency records stay | `crates/storage` upgrade tests v1→current and failed-migration recovery; `tests/account.rs` migration dry run, opt-in adoption, crash resume at every checkpoint, quota; `workspace.test.ts` adoption idempotent; `crates/runtime` old backups restore | Upgrade a real 0.12.x installation on each OS with the pilot build (record in the upgrade report) |
| 5 | Two workspaces: switching drops stale answers, nothing crosses, billing per workspace | desktop e2e "switching workspaces never shows the previous workspace's rows"; `tenant-isolation.test.ts`, `cross-tenant.test.ts`; R7: `portal.test.ts` — a payment in one workspace leaves the owner's other workspace untouched | Pilot user with two teams |
| 6 | Declined / canceled / duplicate payment, renewal failure, downgrade, seat limit, suspension | `billing.test.ts` (failed checkout, duplicates, out-of-order, past due → grace → restricted, cancel at period end, downgrade keeps data, concurrent seats); `portal.test.ts`; `onboarding.test.ts` (seats full, suspended); `admin.test.ts` (payment restriction, security and account suspension); Stripe sandbox suite | — |
| 7 | Owner finds a customer, inspects billing, adds an audited temporary override, resolves a webhook problem — no shell/SQL | R7: `admin.test.ts` "finds the customer, reads billing, adds an audited temporary override and resolves a webhook problem" (one chained test); `support.test.ts` override rules | Owner does it once in the console on staging |
| 8 | Crash, lock contention, unavailable proxy, sleep/wake, interrupted sync, disk full, update failure | crash: `supervisor` and `ipc.rs` reattach/recovery tests; locks: `leases.test.ts`, `sessions.test.ts` (one of twenty wins), `runtime/lock.rs`; proxy: `netproxy/tests/routing.rs`, `browser_network.rs`; interrupted sync: `crates/sync` (network lost at every call, killed at every step, resumed download); disk: `low_disk_keeps_the_previous_backup`, update `low_disk_is_refused…`; update failure: interrupted/corrupt installs, withdrawn browser upgrade rolls back | **Sleep/wake** (no automated test: put a laptop to sleep with a profile open for longer than the lease, wake it: the profile must be closed safely and offered to others, nothing lost); disk full during normal use |

## Known gaps (named, not hidden)
- No automated sleep/wake or clock-jump test; covered by the pilot script above and by the lease design (a lease that
  is not renewed ends; the desktop closes the browser before its lease runs out — `team.rs`).
- No fixture of a real 0.12.x data folder from a customer computer; the upgrade tests build each schema version.
- UI journeys run against in-memory demo backends; the real-API journeys are the CI scripts (`signup-check.ts`,
  `keycloak-sign-in-check.ts`) and `crates/sync/tests/real_api.rs`.
