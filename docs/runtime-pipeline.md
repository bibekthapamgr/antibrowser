# Browser runtime pipeline and version manifest

Decision record: [ADR-0010](adr/0010-runtime-source-and-lifecycle.md). Workflow: `.github/workflows/runtime-pipeline.yml`.

## What the manager trusts
| File | Purpose |
|---|---|
| `runtimes/trusted-keys.json` | Ed25519 public key(s) allowed to sign runtime manifests. Compiled into the manager. |
| `runtimes/manifest.json` | The pinned runtime for this manager release: Chromium version, per-platform URL, SHA-256, size, executable path, macOS code-signature requirement, and the compatibility results it passed. |
| `runtimes/manifest.json.sig` | Detached Ed25519 signature over the exact bytes of `manifest.json`. |

Both runtime files are embedded at build time. They are excluded from formatting (Biome) because reformatting would
invalidate the signature. An empty `manifest.json` means "no approved runtime in this build" (development builds).

## Releasing a new runtime (every upstream Chrome stable update)
1. GitHub → Actions → **runtime pipeline** → *Run workflow* (`sign` ticked). The weekly scheduled run also warns when
   the pinned version is behind upstream.
2. The pipeline resolves the current Chrome for Testing stable, then on Windows x64, macOS arm64 and Linux x64:
   downloads it, installs it **with the manager's own installer** (digest, safe extraction, executable, macOS
   `codesign`), and runs the real-browser compatibility set (`apps/desktop/src-tauri/tests/browser.rs`).
3. The portability matrix runs on fresh runners (each OS's profile restored on every OS). The summary page shows it.
4. Only if all three platforms passed, `manifest.mjs build` writes the manifest (it refuses otherwise) and
   `manifest.mjs sign` signs it with the `RUNTIME_MANIFEST_SIGNING_KEY` secret. Signing refuses a secret that does not
   match the trusted public key, and the result is verified before upload.
5. Download the `runtime-manifest` artifact, commit `runtimes/manifest.json` and `runtimes/manifest.json.sig`, and
   build the manager. Installed managers download the new runtime when the user installs it (milestone 12 automates
   manager updates).

Target cadence (ADR-0001 proposal): upstream High/Critical security fixes in a released manager within 7 days. An
older version must not be kept indefinitely; deferring an update needs a named owner who accepts the risk.

## Compatibility test set
Run per platform against the downloaded runtime (also locally with `PB_TEST_BROWSER=/path/to/chrome`):

| Test | Checks |
|---|---|
| `storage_is_isolated_between_profiles_and_survives_restart` | Cookie, localStorage, IndexedDB, Cache Storage and a service worker written in A are absent in B and present in A after a restart; no `DevToolsActivePort`, no remote-debugging or `--no-sandbox` switch; clean close recorded |
| `a_crash_is_reported_and_never_attached_to_another_profile` | Hard-killed A is CRASHED; B starts its own run with nothing of A's; reopening A keeps its data |
| `repeated_launch_requests_start_one_browser` | Five concurrent launch requests → one operation, one browser main process |
| `ten_launch_close_cycles_stay_clean` | Ten open/close cycles: every run ends clean, Chromium records an orderly exit, no browser left, data persists |
| `portability_spike` | Same-machine restore into a new folder (asserted) and cross-machine restore (recorded) |

## Key management
- The private key was generated by the owner on their own machine and stored only as the GitHub Actions secret
  `RUNTIME_MANIFEST_SIGNING_KEY` (64 hex characters). It never passed through chat or the repository.
- Rotation: generate a new key, add its public half to `trusted-keys.json` (new `key_id`), release a manager with both
  keys, switch the secret and the `key_id` in the workflow, then remove the old key in a later release.
- Compromise: remove the key from `trusted-keys.json` and release a manager immediately; managers that already
  shipped keep trusting it until updated (milestone 12 adds revocation through signed update metadata).

## Local tools
```bash
node scripts/runtime/manifest.mjs resolve                 # current CfT stable + URLs
node scripts/runtime/manifest.mjs verify runtimes/manifest.json runtimes/manifest.json.sig runtimes/trusted-keys.json
cargo run -p pb-update --example install_runtime -- artifact.json chrome.zip <version> /tmp/runtimes
PB_TEST_BROWSER=/path/to/chrome PB_TEST_SWITCHES=--ozone-platform=headless,--disable-gpu,--password-store=basic \
  cargo test -p pb-desktop --test browser -- --test-threads=1      # run as a non-root user (Chromium sandbox stays on)
```
